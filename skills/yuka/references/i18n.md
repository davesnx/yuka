# Messages in more than one language

`yuka i18n` reads one message file for each locale and writes an OCaml
module. Each message is a function. Each `{name}` in the text is a labelled
argument of that function, so a call with a missing argument is a type
error, and a message that is missing in a locale is a build error.

## Message files

Put one file for each locale in a directory, named `LOCALE.messages`:

```
# messages/en.messages
greeting = Hello, {name}!
title = Issues
```

```
# messages/es.messages
greeting = ¡Hola, {name}!
title = Incidencias
```

The rules of the format:

- One message on each line: `key = text`. Spaces around `=` and at the
  end of the line are removed.
- A line that starts with `#` is a comment. Empty lines are skipped.
- A key is a lowercase OCaml name that is not a keyword.
- `{name}` in the text is an argument, a `string`. Write `{{` and `}}` for
  the characters `{` and `}`.
- The file name is the locale: letters, digits and `-`, as `en`, `es` or
  `pt-BR`.

`--base LOCALE` gives the base locale. Each other locale must have the same
keys, and each message must have the same arguments as in the base locale.
If not, `yuka i18n` stops with the file and the line.

The format is one line for each message so that `yuka i18n` reads it with
no parser library.

## The dune rule

Write the module into the library that the server and the islands share,
the library with `(modes native melange)`:

```
(rule
 (targets messages.ml)
 (deps
  (glob_files messages/*.messages))
 (action
  (with-stdout-to
   messages.ml
   (run %{bin:yuka} i18n --dir messages --base en))))
```

## The module

For `en.messages` and `es.messages` above, `Messages` has:

- `type locale = En | Es`, `locales` and `base` (`En`).
- `tag : locale -> string` (`"en"`) and `of_tag : string -> locale option`.
- `locale_param`, so that a route path can have `:locale<Messages.locale>`.
- `locale_codec`, the codec of a `locale`.
- `context`, a `Yuka.Context` with that codec, named `yuka.locale`.
- `current ()`, the locale that the nearest `Context.provide` of `context`
  gives, or `base`.
- A module for each locale, with each message: `Messages.Es.greeting
  ~name:"Ana"` is `"¡Hola, Ana!"`, and `Messages.Es.title` is a string.
- A function for each message that takes the locale first:
  `Messages.greeting locale ~name:"Ana"`.

`Messages.greeting Messages.Es` with no `~name` is a function, not a
string, so it does not compile where a string is necessary.

## A locale route group

Put the pages of each locale below a group with the locale in the path:

```ocaml
Router.group ~path:"/:locale<Messages.locale>" ~layout:Layouts.locale
  [ Router.route Home ~path:"/" ~page:Pages.home ]
```

A path with a locale that is not in the files does not match the group.
The layout gives the locale to the page and to its islands, and each page
sets `lang` on `<html>`:

```ocaml
let locale ~locale ~children () =
  Yuka.Context.provide Messages.context locale (fun () -> children)

let home ~locale () =
  Yuka.Server.page ~lang:(Messages.tag locale) ~title:(Messages.title locale)
    (fun () -> <h1>(Yuka.text (Messages.greeting locale ~name:"Ana"))</h1>)
```

## Islands

An island reads the same locale with `Messages.current ()`. The server
writes the locale into the page once, and the island reads it from there:

```ocaml
let[@client] make () =
  <p>(Yuka.text (Messages.greeting (Messages.current ()) ~name:"Ana"))</p>
```

Only the islands that use `Messages` load it. A page with no such island
loads no message.

## Limitations

- An argument is a `string`. There are no plural rules, and no number or
  date formats. Use `string_of_int` or your own code.
- A message is one line. There is no line break in the text.
- There is no fallback to the base locale: each locale must have each
  message.
- One app has one `Messages` module, because the context name
  `yuka.locale` must be unique.
