# Changes

## 0.1 (YYYY-MM-DD)

First release on opam.

### yuka

- An effect, a hole or an attribute hole whose first run reads no State is not kept: its owner keeps no scheduler node for it, only what it owns, its cleanup or, when it adds an event handler, its disposal. It never runs again, as before. A hole still prints its markers. On the demo page `/w/stress` (2,000 rows) the JavaScript heap goes from 14.60 to 11.86 MB (11.16 MB before every non-constant JSX expression was a hole). The keyed benchmark app goes from 8,502 to 8,524 B gzip, and the JavaScript of the demo pages `/`, `/my` and `/issue/YUK-1` grows by 88 B (@davesnx)
- Breaking: `Form.errors form` gives the errors of a form as a read-only State (`'f Form.errors State.read`), and `Form.field_error` and `Form.form_errors` take its value in place of the form, so every tracked read in user code is a `State.get`. `Form.field_error_view` and `Form.form_errors_view` do not change. `Yuka.Form.field_error` and `Yuka.Form.form_errors` applied to constants are constants in `.mlx` markup. The JavaScript of the demo pages and the keyed benchmark app (8,502 B gzip) do not change. To migrate, write `Form.field_error (State.get (Form.errors form)) field` for `Form.field_error form field` and `Form.form_errors (State.get (Form.errors form))` for `Form.form_errors form` (@davesnx)
- Breaking: `Remote.state` and `Live.state` replace `Remote.status` and `Live.status`. They give the status as a read-only State (`'o Status.t State.read`), with the pending optimistic changes applied, so every tracked read in user code is a `State.get`. `Form.pending` gives a `bool State.read` in place of a `bool`. The demo pages `/` and `/my` grow by 5 B of JavaScript and `/issue/YUK-1` gets 4 B smaller; the keyed benchmark app stays at 8,502 B gzip. To migrate, write `State.get (Remote.state r)` for `Remote.status r`, `State.get (Live.state l)` for `Live.status l` and `State.get (Form.pending form)` for `Form.pending form`; in `<Yuka.Show>`, `status=(fun () -> Yuka.State.get (Yuka.Remote.state r))` (@davesnx)
- In a dev build, a `State.get` that nothing tracks while a component body runs in the browser writes `console.error` with a stack: "[yuka] State.get with nothing tracking it, during the render of a component." The read happens one time and never updates. The check also finds a read in a helper of another module, which the ppx cannot see. It does not fire for a read in markup, a memo, an effect, an event handler, at module level, through `State.peek` or `State.untrack`, or on the server. The ppx wraps a component tag inside a hole in `Yuka.State.runtime_untrack` in place of `Yuka.State.untrack`. A production bundle built with `--define:__YUKA_DEV__=false` has no check code: the raw bytes of each page and the keyed benchmark app do not change, and the gzip bytes of the demo pages move by 19 B or less, because the minifier gives some names in another order (@davesnx)
- Breaking: a `State.get` that reads one time is a compile error. The ppx checks the body of each component, a function bound to `make` at the top of a file or a module whose result contains an HTML or component tag (in `let rec make ... and view ...` only `make`), and each row function of `Yuka.each`. There, a read is an error when it is not inside markup (a child or an attribute value of an HTML tag), a function (an event handler, a helper, `State.memo`, an effect, `Yuka.hole`, the input of `Remote.make`) or `lazy`, as in `let n = State.get count in <p>(Yuka.int n)</p>`, a body result `if State.get open_ then <A /> else <B />`, or `let on = State.get sel = item.id in` at the top of a row. A read in a component prop, also `value` of `Yuka.Context.Provide`, is an error in every place, also when the tag is in a hole: pass the State, `<Label text=name />`, or read with `State.peek`; a prop that is a function, also `read=State.get`, is correct. The ppx finds `Yuka.State.get`, and `State.get` in a file that has `open Yuka` or `module State = Yuka.State`; in other files `State` is a module of the project. `open Yuka.State`, a local open, `include Yuka.State` and an alias such as `module S = Yuka.State`, and after `open Yuka` also `open State` and `module S = State`, are errors, because a read through them is not seen by the check (`module State = Yuka.State` is correct, and an `.mli` can open `Yuka.State`). Use `State.peek` to read one time on purpose. The check makes no code: the bytes of the demo pages and of the keyed benchmark app do not change (@davesnx)
- Breaking: in `.mlx`, each child and attribute value of an HTML tag that is not a constant is a hole. Before, only an expression that contained `State.get` was a hole, so a read through `Remote.status`, `Live.status` or a helper such as `(label ())` did not update; now it does. A constant is an expression that the ppx proves reads no State: a literal, a name, a function, a constructor, tuple, record or list of constants, an HTML tag, `<Yuka.Client>`, a component tag with constant props, `if`, `match` and `let` of constants, an operator or a first-order function of the standard library (`^`, `+`, `=`, `string_of_int`, `String.sub`, `List.length`), `List.map`, `List.filter` and `List.init` with a constant body, a function of the same file whose body is a constant, and `Yuka.text`, `Yuka.int`, `Yuka.float`, `Yuka.fragment`, `Yuka.each`, `Yuka.hole`, `Yuka.with_unique_id`, `Yuka.Form.value`, `Yuka.Form.field_error_view`, `Yuka.Form.form_errors_view` and `Yuka.Status.error_to_string`. A call of a function of another module is a hole. A component tag inside a hole runs its body untracked, so the hole does not run the body again; a plain call `(view ())` is tracked, and a component tag inside a helper that markup calls, `<p>(Helpers.row x)</p>`, is not untracked, so if its body reads a State, the hole builds it again. A function of the same file that an `open`, `include`, `let*`, `let module` or `external` can hide is a hole, and after an `open` of a module of the same file, also a function or module of the standard library.
