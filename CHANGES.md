# Changes

## Unreleased

### yuka

- Breaking: the prefetch level is a rule of the route tree. `~prefetch:`Off`, `` `Hover `` (default) or `` `Visible `` on `Router.make`, a group or a route; the nearest one wins; on an endpoint, an action or a redirect it is a `yuka routes` error. `Yuka.render` has no `?prefetch`. Each page carries the highest level of the tree (`<meta name="yuka-prefetch">`, none for `` `Hover ``), and the browser runs the triggers up to that level. A prefetch sends `Yuka-Prefetch: hover` (hover, focus, press) or `visible` (in view) in place of `1`; when the trigger is above the level of the route, the server answers `204` with `Yuka-Prefetch: <level>` before guards and loaders, and the browser keeps no answer and, for the life of the page, sends no prefetch above that level for the URL (at most 200 URLs kept): one refused request for each such URL, not for each link. The link attribute value `data-yuka-prefetch="visible"` is removed; `"off"` stays. Page answers have `Vary: Yuka-Navigate, Yuka-Prefetch`. `Server.Generated.app` takes `~pages`. To migrate, `Yuka.render ~prefetch:X` becomes `Router.make ~prefetch:X` in `Routes.ml`, and a link with `data-yuka-prefetch="visible"` becomes `~prefetch:`Visible` on its route or group (@davesnx)
- When the answer of a hover, focus or press prefetch arrives, the browser starts to load the island chunks (its `<link rel="modulepreload">`) and the `data-yuka-css` style sheets that it names, so they are in the HTTP cache at the click: each chunk gets a `<link rel="modulepreload">` and each sheet a `<link rel="prefetch">` in `<head>`, once per URL per page. A visible prefetch does this only when a hover, focus or press comes for its link. `` `Lazy `` islands have no preload link and stay lazy. In the demo, a hover on a link from an issue page to `/` loads the `issue_list` chunk and sheet before the click (@davesnx)
- A visible prefetch (`~prefetch:`Visible` or `data-yuka-prefetch="visible"`) starts only while fewer than 4 prefetches are in flight, with `fetch` `priority: "low"`; the others wait, the newest first, and a link that leaves the view before its turn is not fetched. A waiting link takes no place in the 30-entry cache. A hover, focus, press or click on a waiting link fetches it at once. The observer has a 200 px margin. After an action call that succeeds, the visible links in view are prefetched again. Hover prefetches do not change (@davesnx)

- Breaking: in the browser, `Json.of_string` parses with `JSON.parse` and turns the result into a `Json.t`; the hand-written parser is native only. The counter island page goes from 17,946 to 16,779 B gzip and the demo start page from 61,050 to 59,932 B gzip; the keyed benchmark app does not change. In the browser a whole number that fits a 32-bit `int` is `` `Int `` also when written `1.0` or `-0.0`, object keys that are array indices come first, a duplicate key stays once, at its first place with its last value (native keeps every pair), a `\u` escape gives the same string as the character itself, a lone surrogate is not an error, and the error messages for invalid JSON are those of `JSON.parse`. On the server and on native it has the value of `source`. The demo's insights charts read deferred copies of the inputs (@davesnx)

### yuka

- Signals: `State.make`, `State.get`, `State.set`, `State.memo` and `Effect`; a component runs once and only the parts that read a signal update (@davesnx)
- No virtual DOM: only holes and keyed lists update (@davesnx)
- mlx syntax through the `yuka.ppx` ppx, with attribute checks (@davesnx)
- Server rendering and hydration from one element tree, on native and on Melange (@davesnx)

- Actions: declare once, call from the client, run on the server (@davesnx)

- Request cycle in `Yuka.Server`: `yuka-routes --server` writes `Routes_server.app`, and `Yuka.Server.handle` answers a request in a fixed order (assets, trailing-slash 308, redirects, 405 with `Allow`, `OPTIONS` 204, guards, loaders started together, route headers and `cache-control`, `HEAD` without rendering, the streamed page, 404 and 500 pages); a server implements `Yuka.Server.ADAPTER` and calls `Yuka.Server.Make` (@davesnx)
